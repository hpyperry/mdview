# mdview 2.2.0

**发布日期**：2026-10-28

2.2.0 汇总 2.1.0 之后的三项功能与两项流程改进：文件编码检测与 UTF-8 预览、全站导航
分层预载、tar 家族与 ZIP 容器压缩包扩展；同时把测试夹具按 feature 归档、固化人工
复测文档流程，并重新整理文档站的历史资料。

## 新增

- **文件编码检测与 UTF-8 预览**：BOM → UTF-8 校验 → UTF-16 启发式 → chardetng；
  GBK、Shift_JIS、UTF-16 BOM 文件解码为 Unicode 后输出 UTF-8。Markdown 页头与
  源码页显示检测编码（含 BOM/有替换后缀）；搜索正文使用同一解码。
- **非 HTML 文本 charset**：`?download=1` 与 raw 子资源的 `Content-Type` 使用检测
  编码；HTML 响应保持 `text/html` 不带 charset，UTF-32 按二进制下载。
- **全站导航分层预载**：初始只取根 + 三层目录；第 3 层目录按需展开一层。
  `active=<当前路径>` 脊柱让深页一次定位当前文件；桌面悬停约 150ms 预热下一层；
  不再在每个页面空闲时递归扫描并传输整棵树。
- **压缩包格式扩展**：新增 `.tar`、`.tar.bz2`/`.tbz2`/`.tbz`、`.tar.xz`/`.txz`，
  以及 `.jar`、`.war`、`.ear`、`.apk`、`.aar`、`.whl`、`.nupkg`、`.vsix`、`.xpi`、
  `.ipa`、`.aab`、`.epub`、`.cbz`、`.kmz` 等 ZIP 容器；包内 `.xhtml`/`.xht`/`.mf`
  按源码页查看。tar 与 bzip2/xz 解码为纯 Rust；`.tar.xz` 解码器内存上限 128 MiB。

## 改进

- 手动测试夹具按 feature 收拢到 `tests/fixtures/<slug>/`，每个目录可直接作为
  `--root` 启动；新增 `TEMPLATE.md`，把“每个 feature/fix 配一份人工复测文档”固化
  到开发流程、PR 描述和功能矩阵。
- 文档站重整：当前浏览器报告移到 `docs/testing/reports/`，2026-10-20/21 历史报告
  与证据归档到 `docs/archive/testing/`；Python 台账与旧截图、已完成的 Rust 重写
  计划分别归入 `docs/archive/`；新增 ADR 索引与归档索引。

## 兼容性

- `/_nav?__mdview=nav` 的 JSON 形状内部调整：未加载目录省略 `children`，全树模式
  移除；只影响内置导航岛。
- `.xhtml`/`.xht`/`.mf` 现在按源码页打开并进入文本搜索范围；不扩展 HTML 的
  Trust/MIME 路径。
- 没有配置格式或数据迁移；`--safe`、Trust、CSP 与现有 URL 规则保持兼容。

## 已知限制

- 编码检测是启发式的；短小 legacy 文件可能误判，无 BOM 的中文 UTF-16 可能识别
  失败，本轮不提供手动编码覆盖。
- 导航第 3 层目录在展开前不知道是否为空，统一显示展开箭头；单个超大目录仍一次
  列出全部条目。
- 压缩包不支持 `.tar.zst`、RAR/RAR5、单文件 `.gz`/`.bz2`/`.xz`/`.zst` 流与
  Office/ODF 容器；ZIP 容器只做归档浏览，不渲染 EPUB/Office 原生格式，嵌套包不
  递归解包。
- `.tar.xz` 字典超过 128 MiB 的包会被拒绝；大型 `.apk`/`.jar` 仍受 2 万条目与
  1 GB 解压总量限制。
