# mdview 2.2.2

**发布日期**：2026-10-31

2.2.2 是开发工具链版本，**没有任何用户可见变化**：服务端行为、URL 规则、
Trust/CSP、配置格式与浏览器基线全部与 2.2.1 相同。交付二进制功能一致，仅
`--version` 输出变为 `mdview 2.2.2`。

这一版把“本机构建产物会涨到 GB 级”从口头经验变成可度量、可自愈的流程。

## 改进

- **dev profile 固定 `debug = 1`**。本地 debug 构建只保留行号级调试信息，
  panic backtrace 仍能指到具体源码行。实测干净构建
  （`cargo build` + `cargo test --no-run`）：默认 `debug = 2` 为 867 MB，
  `debug = 1` 为 708 MB（−18%）。需要变量级调试时用
  `CARGO_PROFILE_DEV_DEBUG=2 cargo build` 临时覆盖。
- **post-merge 自动清理**。新增 `scripts/git-hooks/post-merge`：合并或 `git pull`
  之后，`target/debug` 超过 2 GB 就删除，保留 `target/release`。hook 永远以 0
  退出，不会挡住 git；`MDVIEW_NO_AUTO_CLEAN=1` 关闭，
  `MDVIEW_CLEAN_THRESHOLD_MB` 覆盖阈值。git hooks 不随仓库分发，每个 clone 需要
  跑一次：

  ```bash
  bash scripts/install-git-hooks.sh
  ```

- **文档与决策记录**。新增 [构建产物与磁盘占用](../guides/build-hygiene.md)
  （三档体积基线、清理命令、清理时机、为什么不引入 sccache）与
  [ADR 0023](../architecture/adr/0023-dev-build-artifact-size.md)
  （`debug = 1` vs `debug = 0`、incremental、依赖图的取舍）；同步 `AGENTS.md`
  代码地图与「容易踩的坑」，并补两份复测文档。

## 背景

Cargo 不回收陈旧指纹：依赖、feature 或 profile 一变就产生新的元数据哈希，旧产物
整套保留；`cargo clean` 也没有「按时间淘汰」的模式。一个长期开发的工作副本因此
攒到 7.7 GB（49 套指纹、221 个 incremental 会话），而交付物只有 4.3 MB。

结论是两件事分开处理：`debug = 1` 让每次构建小 18%，真正的修复是「超过阈值就清」。
一次完整干净重建约 25 秒，清理成本很低。

## 兼容性

- 服务端行为、路由、Trust/CSP、文件编码检测、压缩包范围、浏览器基线
  （Chromium 86+）全部不变。
- 配置格式、CLI 参数、URL 契约不变；无迁移步骤，替换二进制即可。
- 交付产物与 2.2.1 功能一致，仅版本字符串不同。

## 已知限制

- 自动清理只对安装过 hook 的 clone 生效；未安装时仍只有文档约定。
- hook 只处理 `target/debug`，不动 `target/release` 与 `tools/spike/*/target`。
- 体积基线来自 macOS arm64 + rustc 1.96 实测，其他平台只作量级参考。
