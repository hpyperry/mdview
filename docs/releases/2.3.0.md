支持基线从 Chromium 86 提升到 **Chromium 88**。服务端路由、Trust/CSP、文件编码
检测、压缩包范围、配置格式与 CLI 参数不变；运行时仍然零外部请求。

## 新增：导出图片 / PDF

Markdown 文档页工具栏新增两个动作：

- **导出图片**：把正文重建成 SVG `foreignObject` 再绘制到 Canvas，输出白底 PNG
  长图。固定使用浅色调色板，深色主题下导出仍是浅色；默认 2x，画布超限自动降级，
  仍放不下时提示改用 PDF。运行时不发外部请求，不引入第三方库。
- **导出 PDF**：走浏览器打印/另存为。打印样式隐藏顶栏、页头、目录与按钮，强制
  浅色，设置 A4 页边距，并避免代码块、表格、图片跨页断裂。

两个按钮只出现在 Markdown 文档页；无 JS 时隐藏。源码页、目录页、HTML 预览页没有
导出入口。功能编号 [F-95](../reference/features.md)。

已知边界：PDF 依赖浏览器打印对话框，不是服务端直出 `.pdf`；PNG 是栅格长图，极长
文档会降级或建议用 PDF。

## 修复：旧浏览器子资源 MIME

旧 Chrome/Chromium（不发 `Sec-Fetch-*`）请求 `<script src="docs.js">` 时只发
`Accept: */*`，mdview 把它当导航，返回源码页 `text/html`，浏览器严格 MIME 检查
拒绝执行；页面随后报 `window.OpenCollection is not a constructor`。

修复：`fetch_kind` 在无 `Sec-Fetch-*` 时，对 `Accept: */*` + 子资源扩展名
（`js/mjs/cjs/css/json/map/webmanifest/xml`）判为子资源，返回真实 MIME；同时支持
只有 `Sec-Fetch-Mode` 的客户端。`.md`/`.txt` 与 `Accept` 含 `text/html` 的导航
仍显示源码页。功能编号 [F-76](../reference/features.md)。

## 修复：引用块底部空带

引用块有底色时，块内最后一段的 16px 下边距被 padding 挡在色块里，文字看起来贴顶；
含列表时末项还有 4px 残留。修复为上下对称 8px，并用
`blockquote :first-child` / `:last-child` 收掉块内首末外边距；多段引用段间距与块外
间距不变。功能编号 [F-94](../reference/features.md)。

## 修复：Chromium 86–97 的大源码分块

`content-visibility: auto` 依赖 `contain-intrinsic-width: none`（Chrome 98）和
`contain-intrinsic-height`（95）。在 86–97 上声明被丢弃，离屏分块按 0 高度布局，
滚动条与 `#L<n>` 锚点会跳。

修复：把整块优化放进
`@supports (contain-intrinsic-width: none) and (contain-intrinsic-height: 1px)`；
不支持时回退为全量渲染。`source.ts` 的 `replaceChildren` 也加了
`textContent` + `appendChild` 回退。功能编号 [F-31](../reference/features.md)。

## 变更：浏览器基线提升到 Chromium 88

这是本版唯一的支持范围收缩：

- 支持的浏览器从 **Chromium 86+** 改为 **Chromium 88+**；86/87 不再承诺，低于 88
  不支持。
- esbuild target 与 CSS lint 基线同步为 `chrome88`；`inset`/`aspect-ratio`/`:is`/
  `:where` 等 87/88 特性从黑名单移除，89+ 特性继续拦截。
- 依据：2026-11-04 在 Docker + Ubuntu amd64 + Chromium 88.0.4287.0 上跑通 25 项
  CDP 断言，覆盖旧请求头 MIME、`content-visibility` 回退、导出 PNG、主题/导航/
  TOC/放大/搜索。精确的 Chromium 86 构建无法获取，因此不再做没有证据的承诺。

决策记录：[ADR 0024](../architecture/adr/0024-browser-baseline-chromium-88.md)；
实测报告：[legacy-chromium-88-2026-11-04.md](../testing/reports/legacy-chromium-88-2026-11-04.md)。

## 兼容性

- 服务端行为、路由、Trust/CSP、文件编码检测、压缩包范围、配置格式、CLI 参数不变；
  无迁移步骤，替换二进制即可。
- 浏览器要求变为 Chromium 88+；这是本版唯一的不兼容变化。
- 历史 Release 说明与 CHANGELOG 中的“Chromium 86”保留为当时的发布事实。

## 已知限制

- PDF 走浏览器打印/另存为，不是服务端直接生成文件。
- PNG 是栅格长图，超过画布上限会降级或提示改用 PDF。
- 精确 Chromium 86 没有实测；88 的验证环境是 Docker/qemu，真实信创浏览器在滚动、
  字体、Canvas 上仍可能有差异。
- 旧引擎探针仍是临时 harness，未接入 CI；`--headless` 版本探测未做。
- `.md`/`.txt` 的旧客户端 `fetch()` 仍拿到源码页，不是原始字节。
