# 宽屏三列布局与 sticky 外壳

**Status**: accepted（2026-10-19）

用户报告左侧文件导航“没有填充完全”。实测：滚动后侧栏高度是
`视口 - 顶栏`（1013 - 58 = 955px），但 sticky 到 `top: 0`，底部空出 58px。
同一页面的页内 TOC 放在正文顶部时高 **2719px**，正文要到 2889px 才开始。
用户希望 Markdown 页用“左侧导航 / 目录 / 内容”三列，但担心三列太窄。

## 决定

1. **sticky 外壳**：顶部栏 sticky；左侧目录栏与右侧 TOC 列在桌面端
   `top: 58px`、高度 `calc(100vh - 58px)` 并各自滚动。侧栏底部不再留缺口，
   滚动时搜索、主题与导航始终可见。
2. **三列断点**：Markdown 页在 **≥1360px** 使用
   `240px（目录栏） + minmax(0,1fr)（正文） + 220px（TOC）`。
   正文固定 **780px**、16px、1.7 行高，不随空余空间拉宽。
3. **右侧 TOC 列**：只收 h2–h3；sticky、独立滚动；滚动正文时高亮当前标题并
   自动把当前项滚进 TOC 可视区（scroll-spy）。TOC 可由顶栏按钮独立收起并持久化；
   收起后正文仍在剩余区域居中。
4. **降级**：<1360px 回到两列，TOC 回正文顶部的可折叠块；≤900px 目录栏变抽屉。
5. **目录栏范围不变**：仍只列当前目录的子目录与文本文件，不改成全站树。
   `legacy` 这类只有一个文件的目录内容少，是目录本身如此，不是渲染缺失。
6. **修 bug 的判据**：桌面滚动到任意位置，侧栏与 TOC 列的底边都等于视口底边；
   不允许再出现 `视口 - 58px` 的空白。

## 考虑过的替代方案

- **TOC 放中间第二列**：严格执行“导航 / 目录 / 内容”，但正文左右都被固定列夹住，
  更显窄。
- **始终三列**：所有桌面宽度都三列，正文会被压到 640–780，窄屏更挤。
- **两列 + TOC 浮层**：不永久占宽，但少一个常驻大纲。
- **全站文件树**：能填充内容稀疏的侧栏，但用户确认本次保持“当前目录”，
  且全站递归遍历对超大目录成本高。
- **正文随空间放宽到 860 或可拖动**：宽屏利用率更高，但破坏稳定阅读行宽，
  可拖动还会显著增加状态与测试成本。

## 后果

- [ADR 0008](0008-docs-shell-and-reading-typography.md) 的“TOC 在正文顶部”
  与“侧栏 sticky”细节由本 ADR 更新；其余外壳、排版与主题决定不变。
- `html_page` 的 shell 需要为 Markdown 页增加第三列与 `data-toc` 状态；
  `mdview.js` 需要同时生成宽屏 TOC 与窄屏顶部 TOC，并实现 scroll-spy 与开关持久化。
- 浏览器验收新增：滚动后侧栏/TOC 底边贴底、三列断点、TOC 开关、scroll-spy。
- 顶栏 sticky 后，锚点跳转与 `#L<n>` 目标需要考虑 58px 遮挡（加 scroll-margin）。
