# 文档站外壳与阅读排版优先

**Status**: accepted（2026-10-19）；TOC 列与 sticky 外壳细节由
[ADR 0010](0010-three-column-layout-and-sticky-shell.md) 更新

现有页面的 Markdown 内容已经对齐 VS Code，但页面外壳只有面包屑 + 标题 + 工具栏，
目录页和搜索页缺少统一导航，阅读页也重复显示文件名标题。用户要求把 UI 从“服务端
默认样式”提升为真正的文档站。

## 决定

1. **统一外壳**：所有页面（目录、Markdown、源码、搜索、错误、Trust 拦截）共用
   顶部栏 + 左侧目录栏 + 主内容区。
2. **顶部栏**：`mdview` 文字标、当前根目录名、面包屑、搜索框、主题三态切换、
   侧栏开关。
3. **目录栏**：只列**当前目录**的子目录与文本文件，sticky、桌面可完全收起、
   `≤900px` 变抽屉；上级导航交给面包屑。不做全站文件树。
4. **视觉**：GitHub Docs 风格——浅灰页面底、白色内容卡、蓝色强调、圆角与留白；
   深色对应 GitHub Dark。代码块继续使用 VS Code 高亮配色。
5. **阅读排版**：正文 780px、16px、1.7 行高，代码块 13px。Markdown 语义与代码
   高亮仍以 VS Code 为基准，但页面外壳与正文排版不再逐像素对齐 VS Code 预览。
6. **页内目录**：浏览器运行时从 h2/h3 生成可折叠 TOC；服务端不生成标题 id，
   Markdown 输出与 golden 不变。禁用 JS 时没有 TOC。
7. **代码块**：JS 注入语言条（语言名 + 常显复制按钮）；无 JS 时退化为纯代码块。
8. **主题**：系统 / 浅色 / 深色三态，默认系统，手动选择持久化。

## 考虑过的替代方案

- **VS Code 三栏（活动栏 + 资源管理器 + 编辑器标签）**：视觉最接近 VS Code，但
  交互复杂，偏离“静态文档站”。
- **单栏精修**：改动最小，但跨文档导航仍然弱。
- **右侧 TOC 第三栏**：文档站常见，但破坏双栏选择，且需要服务端标题 id。
- **服务端生成 TOC + 标题 id**：会改变 Markdown 输出，破坏 ADR 0005 的“标题无 id”
  与 golden；改由运行时生成。

## 后果

- ADR 0005 的“视觉对齐 VS Code”收窄为 **Markdown 语义、代码高亮与渲染结构**；
  页面外壳和阅读排版由本 ADR 接管。
- `render_markdown` 输出不变，golden 与 134 项渲染兼容测试不受影响。
- 需要更新浏览器验收：新外壳、TOC、语言条、主题三态、侧栏抽屉。
- 无障碍与响应式成为验收项：键盘焦点、抽屉遮罩、对比度、`prefers-reduced-motion`。
