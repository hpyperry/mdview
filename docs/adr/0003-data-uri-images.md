# data URI 图片：只对图片 src 放行 base64

**Status**: accepted

用户报告 `![x](data:image/png;base64,…)` 不渲染。复现结果：行内式退化成字面文本，
引用式退化成 `![x][r]`，尖括号形式同样退化。根因不是解析器不认识 `data:`，而是
`SAFE_SCHEMES` 把它挡在**协议白名单**外：`safe_href()` 返回空串，图片装配于是放弃
整条图片。这条拒绝是 SELFTEST §18.1 修掉存储型 XSS 时加上的，README 与 AGENT.md
都把它写成硬约束。所以这是**安全策略的有意变更**，不是补一个解析分支。

## 决定

1. **只在图片 `src` 放行 `data:`**。链接、裸 URL、尖括号自动链接继续拒绝。判据挂在
   **消费方**（图片装配）而不是全局协议表上 —— 同一段 `data:` 文本，进 `<img src>`
   放行，进 `<a href>` 拒绝。
2. **只接受 `data:image/<类型>;base64,<数据>`**。`;base64` 必须是媒体类型部分的
   **最后一个**参数（允许 `;charset=…` 这类参数在它前面）—— 浏览器只认这个位置，
   写在中间时它会按百分号编码解释 payload。类型集合与 `IMAGE_EXT` 对齐：
   png / jpeg / gif / svg+xml / webp / bmp / x-icon / avif。SVG **不**排除：同样内容
   的 `.svg` 文件本来就能以 `<img>` 显示；`<img>` 里的 SVG 在现代浏览器中按静态图片
   加载（不执行脚本、不加载外部资源），data URI 只是换一种运输方式。
3. **不支持非 base64 的文本形式**（如 `data:image/svg+xml,<svg…>`）。二进制图片实践
   中都是 base64；放开文本形式还要为它再设计一套百分号解码规则。
4. **不为单张 data URI 另设大小上限**。整个 `.md` 已受 `--max-preview`（默认 20 MiB）
   约束，新增阈值只会制造一个不透明的失败模式。
5. **照常参与图片放大**。数据 URI 图片不在链接里时，仍包**包裹链接**；有 JS 时遮罩
   正常。禁用 JS 时浏览器通常拦截 `data:` 顶层跳转，点击无反应 —— 但图片本来已内联
   显示，不存在「别处的原图」。
6. **裸 HTML `<img>` 仍整体转义**。拒绝或畸形的 data URI 仍按字面文本退化，与现有
   危险协议的处理保持一致。

## 考虑过的替代方案

- **保持拒绝**：零风险，但原始诉求无解；用户只能把图片拆成独立文件，丢失单文件
  可移植性。
- **`data:` 全局放行**：拒绝。`data:text/html` 放进链接或顶层导航是可执行的攻击面，
  与这次需求无关；放宽的边界应该只覆盖「图片上下文」。
- **把 data URI 落盘成临时文件再指向它**：拒绝。服务端要获得写权限，引入路径与磁盘
  填满问题，还破坏「预览不落盘」的语义；收益只是让 `src` 看起来像普通路径。
- **只放行光栅图、排除 SVG**：拒绝作为能力边界。SVG 已经能作为文件被同一台服务以
  `<img>` 显示；在 data URI 上单独禁它是一种防御剧场，代价是同类内容一种写法坏、
  一种写法好。若将来出现 `<img>` 之外的新消费方（例如允许导航到原图），必须重新评估。
- **单张 data URI 设上限**：拒绝。阈值只能拍脑袋，而且会让「大图能显示、稍大的图变成
  一段字面文本」，失败方式比体积增长更糟。

## 影响与代价

- 三种 Markdown 目标写法（行内、引用式、尖括号）共用 `_target_attrs`，一起生效；
  裸 HTML 不在范围内。
- 页面 HTML 会把同一段 data URI 写两遍（`src` 与包裹链接的 `href`），所以最大
  体积约为 `.md` 上限的两倍；浏览器还要为解码后的图片分配内存。这是用户选择内嵌
  的固有代价。
- 测试必须钉住**消费方边界**，而不只是「`data:` 被拒」：`data:image/…` 在 `<img>`
  里产属性；同样的串在 `[x](…)` 里不产 `href`；`data:text/html` 在图片里也拒绝；
  大小写混写、引用式、尖括号、缺逗号 / 缺 `;base64` / `;base64` 不在末位各一条。
  旧断言 `test_rejected_protocol_stays_literal` 里 `data:text/html` 那条保持不变。
- 文档要同步：README 的 XSS 小节不能再说「`data:` 一律不产出属性」；AGENT.md
  硬约束 3 要写清「按消费方开口」；GLOSSARY 增加协议白名单与数据 URI 图片。
- 实现收尾仍走仓库纪律：两套测试 → `tools/minify.py` 重新生成 `dist/` →
  同步 README / tests/README.md / SELFTEST.md 的计数与描述。
