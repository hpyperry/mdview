# 压缩包预览：虚拟包路径 + 临时解压缓存

**Status**: accepted（2026-10-21）

## 背景

需要在线预览 ZIP/tar.gz/7z。直接在内存里按条目读对 tar.gz 与 solid 7z 不可行；
把解压目录暴露成普通站点路径又会泄漏内部路径、让 URL 随重启失效。选择“先解压到
进程私有临时缓存，再把压缩包映射成虚拟目录”。

## 决定

### 1. 格式

支持 `.zip`、`.tar.gz`/`.tgz`、`.7z`。RAR 与未压缩 `.tar` 不在本次范围。
加密包、多卷包、损坏包整包拒绝并给出明确错误。

### 2. 虚拟包路径

| URL | 行为 |
|---|---|
| `/a.zip/` | 包根目录列表 |
| `/a.zip/docs/` | 包内目录列表 |
| `/a.zip/docs/x.md` | 包内条目，走现有 Markdown 渲染 |
| `/a.zip/docs/x.html` | 包内 HTML，走 ADR 0015 的预览/源码双模式 |
| `/a.zip?download=1` | 下载原压缩包 |
| `/a.zip/docs/x.md?download=1` | 下载解压后的条目 |

- 路径里**只有第一个压缩包段是容器**；之后再遇到 `.zip`/`.tar.gz`/`.7z`
  按普通条目处理，不做嵌套解压。
- 真实目录优先：磁盘上叫 `foo.zip` 的目录仍按目录处理。
- 压缩包检测发生在 `--max-preview` 下载判断之前；容器本身可以大于 20 MB，
  条目预览仍受 `--max-preview` 限制。
- 相对链接天然成立：包内 Markdown 渲染时 `doc_rel` 是 `a.zip/docs/x.md`，
  图片/链接改写成 `/a.zip/docs/...`，由同一路由映射回解压目录。
- 目录列表、Markdown 渲染、源码页、图片/PDF 内联与下载都复用现有实现；
  面包屑显示 `站点 / a.zip / docs / x.md`。

### 3. 解压与缓存

- 首次访问解压整包到进程私有临时根（0700），按
  （规范化路径, mtime, size）缓存；同包单飞，避免并发重复解压。
- 进程退出清理临时根；启动时尽力清理超过 24 小时的旧 `mdview-*` 目录；
  缓存总量上限 4 GB，按最近使用淘汰。
- 压缩包变化（mtime/size）生成新缓存键；旧缓存淘汰。
- 条目 mtime 尽量保留原始时间；无法保留时列表不显示修改时间，避免把解压时间
  当成文件时间。

### 4. 安全上限（中等档）

- 压缩包 ≤ 200 MB；解压总量 ≤ 1 GB；条目数 ≤ 20,000；单条 ≤ 100 MB。
- 超限整包失败，不做部分预览；流式解压时达到总量立即中止并删除临时目录。
- 拒绝：加密、多卷、绝对路径、`..`、NUL/反斜杠、软链/硬链、设备/管道文件、
  重复规范化路径与 Windows 大小写冲突路径。
- 条目路径只用于映射到服务端生成的安全磁盘名；用户路径永远不直接拼接到磁盘。
  条目访问同样做 canonicalize + `starts_with` 检查。
- 文件名编码：ZIP 有 UTF-8 标志按 UTF-8；否则 UTF-8 → GBK，再由 `zip` crate
  做 CP437 回退。tar 的字节名按 UTF-8 → GBK，仍失败则 lossy；7z 使用其 UTF-16
  名称。显示用 lossy，无法解码的条目仍以下载形式可达。

### 5. UI 与导航

- 目录/导航里压缩包是一个文件节点，点击进 `/a.zip/`；列表头部显示包名、大小、
  条目数与“下载压缩包”。
- 包内条目复用目录列表、Markdown 渲染、源码页、图片/PDF 内联与 HTML 双模式。
- 全站导航只显示压缩包文件，不展开包内目录；搜索只匹配包名/路径，不扫包内正文；
  包内条目不进搜索结果。
- 嵌套压缩包按普通文件列出，只提供下载，不自动解压。
- `--safe` 下压缩包与其它非 `.md`/图片文件一样不可见（404），不进入包内。

## 考虑过的替代方案

- **查询参数 `/a.zip?entry=docs/x.md`**：相对链接会指到站点根，需要在渲染器里
  加虚拟 base 或重写 URL，链接/图片容易断；否决。
- **隐藏 hash 路由 `/_archive/<hash>/...`**：URL 不含原包名，面包屑与分享不直观；
  否决。
- **内存虚拟文件系统**：tar.gz/7z 随机读不可行，大包内存压力高；否决。
- **直接暴露临时解压目录**：泄漏内部路径，包删除/重启后 URL 失效；否决。
- **递归解压嵌套包**：压缩炸弹与解压链风险放大；本次不做。

## 后果

- 首次打开有解压延迟；大包可能明显慢，之后走缓存。
- 磁盘缓存需要清理策略；崩溃可能留下临时目录，启动清理兜底。
- 7z solid 包必须整包解压；这是选择临时缓存的直接代价。
- 包内条目没有全站搜索与导航展开；需要按虚拟路径直接访问或从包列表进入。
