# Markdown 搜索命中定位到渲染块

**Status**: accepted（2026-10-20）

搜索结果里的 Markdown 命中行需要跳到“预览后的行”，但渲染页没有源码行边界：
源码页有 `#L<n>` 锚点，渲染页没有。直接回到源码页精确，但用户明确要求留在
渲染预览；给每个源码行生成锚点又会破坏 Markdown 结构。

## 决定

1. **渲染页启用 sourcepos**：服务端调用
   `render_markdown_with_sourcepos`，让 comrak 给渲染块输出
   `data-sourcepos="起始行:列-结束行:列"`。默认的 `render_markdown` 保持无
   sourcepos，golden 与渲染兼容测试不受影响。
2. **搜索条目整行跳转**：Markdown 正文命中链接到 `/path#L<n>`；文件名命中与
   文件条目链接到 `/path`；不再有独立的“打开文档/打开文件”按钮。
3. **客户端块映射**：新增 `linetarget` 岛。页面加载或 `hashchange` 时读取
   `#L<n>`，在渲染块中找包含该行的最小块（段落、标题、列表项、代码块、表格行
   等），滚动到块首并短暂高亮 2.4 秒。空行、被 front matter 消费的行等找不到
   精确块时，回退到最近的后续或前置块。
4. **降级**：无 JS 时搜索链接仍打开渲染页，但不会滚动到命中块；源码页的精确
   `#L<n>` 行锚点保持不变。

## 考虑过的替代方案

- **继续链到源码页 `?raw=1#L<n>`**：精确到行，但用户要求在渲染预览里定位。
- **给每个块生成 `id="L<n>"`**：只能命中块起始行，且需要服务端预先知道搜索
  行对应哪个块；sourcepos + 客户端映射更灵活，也不污染标题 id 语义。
- **逐源码行注入锚点**：会打散 Markdown 的块结构，等于重写渲染器。

## 后果

- 渲染页 HTML 增加 `data-sourcepos` 属性（块与行内节点都会出现）；这是渲染页
  的体积成本，换取无需重建索引的行定位。
- 行定位是块级近似，不保证字符级；同一段内的多行命中会落到同一个块。
- 文档页 `data-islands` 增加 `linetarget`；浏览器验收覆盖“命中行链接 → 渲染页
  滚动 + 高亮”。
- 后续若要做字符级定位，需要扩展渲染器或引入源映射，不在本 ADR 范围内。
