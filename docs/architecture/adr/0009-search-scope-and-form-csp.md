# 搜索：放行同源表单、覆盖文本文件、文档优先

**Status**: accepted（2026-10-19）；CSP `connect-src` 由
[ADR 0013](0013-full-site-navigation-island.md) 为 `/_nav` 恢复为 `'self'`；
搜索结果条目于 2026-10-20 改为整行链接，Markdown 行定位见
[ADR 0014](0014-markdown-line-target.md)

用户反馈页面里的搜索“无法使用”。复现结果是服务端搜索正常，但 CSP 的
`form-action 'none'` 让浏览器拒绝提交搜索表单；同时搜索只扫 `.md`，结果一律跳到
`?raw=1#L<n>`，与“在目录里找东西”的预期不符。

## 决定

1. **CSP 放行同源表单**：把 `form-action 'none'` 改为 `form-action 'self'`。
   这是与 VS Code `'none'` 的明确偏差；本站没有状态变更型表单/接口，搜索是
   唯一用途。表单在无 JS 时也可用。
2. **搜索范围**：
   - **文件名**覆盖所有文件（含图片/PDF），用于定位资源；
   - **正文**只覆盖 Markdown 与按文本处理的文件；二进制不扫描；
   - 跳过隐藏目录、`SKIP_DIRS`、超过 `--max-preview` 的文件。
3. **实时扫描**：不建索引；每次请求扫盘，与外部编辑保持一致。限制文件数与
   每文件命中数，避免大目录拖垮单请求。
4. **结果组织**：按文件分组，显示路径、命中数、行号与片段。每条命中整行是
   一个链接：Markdown 正文命中跳到渲染页的对应块（`#L<n>`，见
   [ADR 0014](0014-markdown-line-target.md)）；文件名命中与文件条目跳到文件
   开头。不再提供独立的“打开文档/打开文件”操作链接，行号与片段本身承担
   结果条目的语义。
5. **搜索交互**：无 JS 表单提交；JS 追加 `/` 聚焦、Esc 清空、结果词高亮。

## 考虑过的替代方案

- **JS 接管提交、CSP 保持 'none'**：无 JS 时搜索仍不可用，违背“禁用 JS 也能读”
  的基线。
- **启动时建索引**：查询快，但启动成本、内存占用与外部编辑失效策略都不划算；
  常规文档库实时扫描足够。
- **仅 Markdown / 仅文件名**：实现更小，但用户明确需要覆盖文本源码与资源定位。

## 后果

- ADR 0006 的 CSP 策略更新：`form-action 'self'`；其余 `frame/base/object 'none'`
  与 nonce-only `script-src` 不变。
- 搜索是 O(文件数) 的实时扫描；超大目录会变慢，但不会静默返回陈旧结果。
- 需要在浏览器验收中覆盖“点搜索按钮真的能提交”和无 JS 搜索。
- 搜索结果页必须继续转义片段；查询词高亮只能由 JS 在文本节点上做，不能拼接 HTML。
- 搜索结果行是整行链接；Markdown 行定位依赖渲染页的 `data-sourcepos` 与
  `linetarget` 岛。禁用 JS 时链接仍打开文档，但不会滚动到命中块。
