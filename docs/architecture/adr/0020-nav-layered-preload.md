# 全站导航分层预载与按需展开

**Status**: accepted（2026-10-26）。修订
[ADR 0013](0013-full-site-navigation-island.md) 的“全站树一次返回”和“空闲预取整棵树”；
导航仍是默认收起、不跨页缓存的浮岛。

全站导航最初在每个页面空闲时递归扫描并返回整棵树。文档库变大后，弱机上的页面
后台成本变得明显：20,000 个目录 / 80,000 个文件的合成树产生 36.4 MB JSON、约
765 ms 服务端耗时，其中 85–91% 是递归 `readdir`，浏览器 `JSON.parse` 只占约
7.5%；5,000 个目录 / 20,000 个文件也要 8.75 MB、约 161 ms。瓶颈是“每次页面都
重扫全树”，不是传输或解析。单纯把树截到三层能减少扫描，但深页会失去当前文件
定位，每次展开都变成一次等待，体验又太“懒”。

## 决定

1. **三层预载**：初始 `/_nav?__mdview=nav` 只返回根、第 1、2、3 层目录节点。第 3
   层目录是占位，不返回其内容；根与第 1/2 层目录内的文件直接返回。目录层的
   计数口径是“根的直接子目录为第 1 层”。
2. **当前路径脊柱**：初始请求可带 `active=<当前路径>`。服务端额外返回当前文件
   祖先链上的目录内容（含同级条目），即使超过三层；深页打开导航一次请求即可
   展开祖先并高亮当前文件，不做逐级请求瀑布。
3. **按需展开一层**：`/_nav?__mdview=nav&dir=<相对路径>` 只返回该目录的直接子项。
   `dir` 必须是根内真实目录；拒绝 `..`、绝对路径、反斜杠与 NUL，canonicalize 后
   必须 `starts_with(root)`。隐藏目录、`SKIP_DIRS`、safe 过滤、排序与 `partial`
   容错规则与初始响应一致。
4. **页面内缓存与去重**：前端按目录缓存已加载子项，同一目录的并发请求合并；
   展开未加载目录显示行内加载态，失败可重试，空目录显示空态。缓存只活在当前
   页面，不跨页持久化。
5. **克制的预热**：桌面端指针在目录行停留约 150ms 才预取该目录一层；触屏与键盘
   不预热。点击/回车时若已有预热请求，直接复用，不再发第二次。
6. **空闲预取保留但受限**：页面空闲时仍预取，但只取三层 + 当前路径脊柱；不跨页
   缓存，不做服务端 TTL。localStorage 记住的深层展开状态只在打开导航时按祖先链
   补加载，不进入页面空闲预取。
7. **不保留全树模式**：`/_nav?__mdview=nav` 不再有“一次返回所有层”的分支；需要
   深层内容只能通过 `dir` 逐层取。

## 考虑过的替代方案

- **只做三层 + 纯按需展开**：实现最小，但深页打开导航要逐级请求祖先链，用户会
  看到多段加载行；与“不要太懒”的目标冲突。
- **自适应节点预算**：按节点数截断能硬性限制宽树，但同一层的兄弟目录可能有的
  加载、有的截断，树形不可预测；三层口径更容易解释和验收。单个超大目录的
  分页/虚拟滚动另开 Issue。
- **服务端整树缓存 + TTL**：重复页面能变快，但首访仍要扫全树，且目录变化会短暂
  不可见；ADR 0013 已明确不做 TTL 缓存。
- **流式返回全树**：首屏更快，但弱机后台仍要完成整树扫描与 JSON 构建，和“不要
  全都加载”冲突。

## 性能复测（2026-10-26）

在同一量级的合成树（20,850 目录 / 83,585 文件）上，新初始 `/_nav` 为 **55.6 KB /
2.3 ms**（752 个节点），单目录 `dir=` 为 **0.9 KB / 0.4 ms**，`active` 脊柱为
**55.9 KB / 1.9 ms**。旧全树基线在 20,000 目录 / 80,000 文件上是 36.4 MB /
765 ms；两次树的形状不同，但量级一致，足以说明瓶颈已从全树扫描转为三层预载
加单目录读取。

## 后果

- 初始导航成本由“全树节点数”变为“三层节点数 + 一条当前路径”；深层目录越多，
  收益越明显。
- 展开第 3 层及更深的目录会多一次 `/_nav?...&dir=` 请求；桌面端悬停预热把它
  隐藏掉，触屏上是一次本地小请求。
- 第 3 层目录在首次展开前不知道是否为空，统一显示展开箭头；展开后空目录显示
  空态。
- 服务端新增 `dir` 路径校验与单层读取；测试需要覆盖路径穿越、根外符号链接、
  非目录、safe/hidden/partial 与 `active` 脊柱。
- README、AGENTS 的导航约束、features 与浏览器探针都要同步更新。
